# 文档编写规则

本规则适用于当前维护的说明、接口文档和部署步骤。项目相关对话也使用相同的简明表达与术语原则。
对话明确区分实测、推断和未验证项。历史报告保留测量值、日志、命令和人工确认原文。
历史报告中的结论只代表报告日期；使用当前接口时，先阅读 [文档入口](../README.md#文档)。

## 英文

以 [ASD-STE100 Issue 9](https://www.asd-ste100.org/assets/files/ASD-STE100_ISSUE9.pdf) 为编写依据。
该规范包含写作规则和受控词典。词义、词性和项目技术术语都需要审查；句长检查不能证明全文符合规范。

- 操作句使用祈使句，每句只写一个操作，每句最多 20 个词。
- 说明句每句最多 25 个词。每段最多 6 句，只说明一个主题。
- 使用主动语态。说明中只有确有必要时才使用被动语态。
- 使用词典批准的词性和词义。例如，使用 `do a check`，避免把 `check` 用作动词。
- 同一组件、动作和状态使用同一术语。避免比喻、缩略口语和省略主语造成的歧义。
- 先说明操作条件，再写操作。将操作步骤与原理说明分开。
- 命令、路径、标识符、JSON 键和日志原文保持准确，不为满足词表而改名。
- 第一次出现缩写时说明含义；代码标识符与接口表可保留原名。

当前维护的英文操作文档为 `frontend/DEPLOYMENT.md`、`state/API.md`、
`tools/REFERENCE_SPEECH.md` 和 `rvc-golden/README.md`。
这些文档按 STE 规则整理。仍需人工逐词审查，不声明已经通过完整符合性认证。

### 项目技术术语

以下术语用于软件和音频领域。使用时保持同一含义；一般词不能任意改列为技术术语。

| 英文术语 | 中文术语 | 项目含义 |
| --- | --- | --- |
| backend / frontend | 后端 / 前端 | 原生服务 / 浏览器界面 |
| daemon / supervisor / worker | 守护进程 / 监督程序 / 工作进程或线程 | 分别指 `mozart_stated`、Python 启动器、具体处理单元 |
| reference speech | 参考音色播报 | 根据参考 WAV 合成翻译文本 |
| voice profile | 音色配置 | 参考音频及其版本、语言和引擎信息 |
| checkpoint / asset / engine | 检查点 / 资产 / 推理引擎 | 训练权重 / 部署文件 / 执行模型的运行时对象 |
| Generator / HuBERT / RMVPE | 保留原名 | RVC 合成器 / 特征模型 / 基频模型 |
| Golden reference | Golden 参考 | 已确认的原始 PyTorch 参考路径及其产物 |
| pitch / coarse pitch / F0 | 音高 / 离散音高 / 基频 | Generator 音高条件；具体张量以捕获记录为准 |
| frame / block / chunk | 帧 / 块 / 片段 | 20 ms 契约帧 / 推理块 / 播报文本及音频片段 |
| rolling past context | 滚动历史上下文 | 已经收到的音频历史 |
| lookahead | 前视上下文 | 需要等待的后续输入 |
| bypass / underrun / overrun | 旁路 / 欠载 / 溢出 | 跳过推理 / 输出不足 / 输入积压 |
| queue / job / deadline | 队列 / 任务 / 截止时间 | 待处理项 / 一项逻辑工作 / 任务时间限制 |
| ASR / TTS / SSE | 自动语音识别 / 语音合成 / 服务器发送事件 | 字幕、播报和事件传输组件 |
| RVC / ONNX / TensorRT / CUDA / ALSA / PipeWire / SPSC / SOLA | 保留原名 | 算法、模型格式、运行时、设备接口或缓冲与拼接方法 |

软件技术动词包括 `build`、`compile`、`decode`、`encode`、`export`、`normalize`、
`preload`、`proxy`、`resample`、`synthesize`、`load`、`reset`、`run` 和 `return`。这些词只用于对应的软件或音频操作。

## 中文

本次检索未确认与 STE 受控词表直接对应的通用中文标准。中文整理参考下列规范的适用范围：

- [GB/T 19678.1—2018](https://std.samr.gov.cn/gb/search/gbDetailed?id=FYgfNOdxgnU%3D&mode=p)：使用说明的结构、内容和表示方法。
- [GB/T 15834—2011](https://www.moe.gov.cn/ewebeditor/uploadfile/2015/01/13/20150113091548267.pdf)：中文标点符号。
- [GB/T 1.1—2020](https://std.samr.gov.cn/gb/search/gbDetailed?id=A24AF19F41445C2EE05397BE0A0A5E0D)：标准化文件的结构和起草规则。

上述规范用途不同，不能合称为“中文版 STE”。本项目采用以下编写约定：

- 一句说明一件事；一句操作只包含一个主要动作。
- 写明条件、动作和可观察结果。删除宣传性措辞和没有证据的保证。
- 使用统一中文术语。首次使用英文术语时说明含义；标识符保持原样。
- 分清“已实现”“已验证”“未实现”和“待验证”。每个测量值注明适用配置或报告。
- “必须”表示必要条件；“建议”表示可选做法；“可以”表示已知能力。
- 中文正文使用中文标点。命令、路径和代码使用其原有符号。
- 数值与单位之间留空格，例如 `320 ms`、`48 kHz`、`8 GB`。代码与引用原文除外。
- 避免用旧的孤立基准推断当前整机性能。硬件能力结论限定到测试过的平台和配置。

## 验收

1. 对照代码审查路由、参数、路径和状态行为。
2. 确认命令中的构建目录与启动目录一致。
3. 检查内部链接、代码块和中英文接口示例。
4. 对英文执行句长检查，再人工审查词义、词性和技术术语。
5. 保留历史证据和人工确认原文；用归档说明标明其适用日期。
