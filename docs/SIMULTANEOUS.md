# 稳定从句提交实验

本功能默认关闭。启动参数为 `--stable-clauses`，需要覆盖率优先策略。
播放速度保持原值。完整原文仍按原识别句显示和保存。

## 提交规则

- 前缀须在最近三次识别更新中保持一致。三次更新的时间跨度至少为 600 ms。
- 边界须为标点，或“然后、但是、不过、反正、接着、完了”等连接词之前的位置。
- 边界前至少保留 10 个字符，边界后至少观察到 4 个稳定字符。
- 数字尚未结束、条件关系未确定、括号未闭合或末尾明显未完时，继续等待。
- 每个原识别句最多提前提交两次。最终结果提交全部剩余文字。

这些规则是保守启发式，不能证明语义已经稳定。
没有满足条件的边界时，系统仍等最终识别结果，不按固定字符数强行切分。

翻译工作进程按提交顺序处理片段。
模型最多接收同一句内前两个成功片段的原文作为上下文，并只翻译当前新增原文。
前句原文和已有译文不进入模型上下文。
若不同原文得到与前段完全重复的译文，系统移除上下文后重试。
数字、人物关系和候选译文检查继续执行。
检查失败的非空候选仍按现有降级策略显示和播报。

## 原文修订与可追溯性

若识别改写已提交前缀，系统暂停提前提交，并等待最终结果。
最终前缀仍不一致时，系统提交完整最终原文作为更正。
更正语音以 `Correction.` 开始。界面保留修订警告。
这会重复部分内容；系统不能撤回已播放的音频。

父字幕继续使用原来的 `utterance_id`，修订号递增。
`translation_segments` 保存每个片段的原文、字符范围、提交时间、译文、错误和播报任务。
字符范围采用 Python 字符串索引，起点包含，终点不包含。
播报请求使用独立标识 `<utterance_id>/part/<index>`，避免同句后续片段被去重。
聚合译文在后续临时字幕更新时仍可见。

翻译片段使用独立 SQLite 队列 `translation-clauses.sqlite3`。
父字幕状态也保存在该数据库中。内存最多缓存 128 个父字幕。
等待任务恢复原标识，播报服务可据此去重。

## 使用与回退

在已经配置好的实时启动命令中添加：

```text
--stable-clauses
```

该选项可以与 `--early-audio` 配合使用。
提前输出音频仍需指定独立运行时；详见[播报说明](../tools/REFERENCE_SPEECH.md)。

移除 `--stable-clauses` 后，新输入恢复整句翻译。
若实验队列中仍有等待任务，先使用该选项完成队列处理，再切回普通模式。
两个模式使用不同队列，不会自动迁移等待任务。

本实验不改变识别模型、识别断句、生成步数、语速或 RVC 路径。
验收须同时报告原文范围覆盖、实际播报完成率、首播等待、片段间隙和语义变化。

## 语义判断与译文提交

2026-10-09 的独立短测没有得到可用的原文完整性判断器。
现有 0.8B 模型在四组提示与输出方式下均退化为全部等待。
该判断脚本没有接入实时处理路径，也没有新增启动选项。
GitHub 方法对照、样例分母、耗时定义和后续设计见[调研与短测报告](../reports/realtime-patches-20261008/SEMANTIC_GATE.md)。

## 小型句界分类器实验

该模式使用 NNSplit 0.5.8 的简体中文句界模型。
权重约为 4 MB。模型在 CPU 单线程上运行，不调用翻译模型做判断。
运行环境需要 `numpy` 和 `onnxruntime`，不需要安装 NNSplit 或 PyTorch。
模型和[推理参考代码](https://github.com/segment-any-text/wtpsplit/tree/7193727df7e497b0993ad96688f34c3a6add0618)采用 MIT 许可证。
许可证原文保存在 [NNSPLIT.txt](../tools/licenses/NNSPLIT.txt)。

下载固定版本模型：

```bash
.venv/bin/python tools/fetch_boundary_model.py
```

下载程序直连官方 GitHub，并验证 SHA-256。
默认路径为 `~/models/mozart-boundaries/nnsplit-zh.onnx`。
若已有文件的摘要不同，程序报告错误，不覆盖该文件。
实时运行时不会自动下载模型。

在既有实时启动命令中添加：

```text
--boundary-model /absolute/path/to/nnsplit-zh.onnx
```

该参数自动启用分段提交，需要覆盖率优先策略。
未指定模型时，原有整句模式和 `--stable-clauses` 规则均保持原行为。
分类器模式采用以下实验参数：

- 原文前缀至少经过两次识别观察，观察时间跨度至少为 200 ms。
- 提前提交的片段至少包含 8 个字符，切分位置之后至少保留 4 个稳定字符。
- 默认句界概率阈值为 `0.5`，由 `--boundary-threshold` 调整。
- 新增稳定原文达到 28 个字符时，允许使用长度限制切分，即 24 个字符加 4 个前视字符。
- 长度限制切分选择 8–24 字符范围内得分最高的位置；没有模型边界时也可切分。
- `--clause-max-chars` 调整上述 24 字符限制，允许范围为 12–64。
- 每个原识别句最多提前提交 8 次；最终识别提交全部剩余原文。

分类器不要求原文已有标点，也不沿用旧模式的完整条件句限制。
这符合当前允许较粗糙输出的实验目标，但可能切开条件、否定或金额表达。
该模型预测句界，不证明语义完整；长度限制切分更不具有完整性保证。
日志中的 `boundary_classifier.cut.reason` 区分 `model` 与 `length_limit`。

分类线程在字幕读取线程之外运行。等待区只保留最新一份请求。
模型每次最多处理 120 个字符，保留最多 24 个字符的已提交左侧上下文。
晚到结果须与当前稳定前缀和已提交范围一致，不能覆盖新原文或最终识别。
模型推理错误会显示提示；最终翻译仍处理完整剩余原文。
现有翻译检查、失败候选播报和明确更正流程继续执行。

该模式使用独立队列 `translation-boundaries.sqlite3`。
退出或回退前，使用相同选项完成等待任务，再移除 `--boundary-model`。
原文范围、分类依据、模型摘要和判断耗时随片段保存。
本模式不改变播放速度、音色模型或生成步数。

2026-10-09 的单次 120 s 对照中，23／23 句完成播报并保留完整提交范围。
最终识别事件至首个音频块开始播放的延迟中位数由 10.559 s 降至 8.188 s。
该计时不含识别前等待；实验仍有播放积压，也未完成人工听检。
配置、分类耗时、片段间隙与限制见[分类器实测报告](../reports/realtime-patches-20261008/BOUNDARY_CLASSIFIER.md)。
