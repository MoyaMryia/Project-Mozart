## 丢帧证据与代码确认

| 计数位置 | 结果 |
| --- | ---: |
| 预处理器最终发送 | 26955 帧 |

| 后端 UDP 接收 | 26854 帧 |
| 后端 UDP 发送 | 26850 帧 |
| 后端 UDP 丢弃 | 4 帧 |
| 中继保存的连续返回包 | 26849 帧，索引为 1–26849 |
| 预处理器采集溢出 | 0 |

中继收到下一包后触发 `Output frame sequence gap or duplicate`，退出码为 1。
触发包在写入前被拒收，所以中继保存数比后端发送数少 1。
后端的接收、发送与丢弃计数相互吻合。

代码确认：[UdpStream::ReadFrame](../../IO/src/udp_stream.cpp#L381) 在积压超过 4 帧时丢弃旧帧，只保留最新帧。
积压为 5 帧时，该路径会丢弃 4 帧；环缓冲区满时也会增加同一丢弃计数。
本次日志确认后端丢帧，具体触发路径留作下一次诊断任务。
