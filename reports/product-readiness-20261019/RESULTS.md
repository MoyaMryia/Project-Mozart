# 产品交付代码审核

日期：2026-10-19，UTC+8。

当前项目具备工程样机和受控演示能力，完整产品交付还缺少运行闭环、故障恢复、质量验收和可复现部署。
优先收尾现有主链路。PipeWire、零样本转换和更换模型属于后续能力。
本轮保留全部既有代码及失败记录，新增审核报告和证据。

## 交付判断

| 交付形态 | 判断 | 主要依据 |
| --- | --- | --- |
| 开发者操作的实时变声演示 | 已有支持证据 | 指定配置的完整独立变声返回 209442/209442 帧，见[完整诊断](../diagnostic-20261019/RESULTS.md#独立变声) |
| 中文识别、英文字幕及参考播报演示 | 可以继续验证 | 最新固定字幕重放完成 166/175 段，存在错误和播放等待 |
| 用户打开设备即可使用的完整系统 | 暂缓交付 | 缺少统一启动、就绪判定、物理音频故障反馈和重连恢复 |
| 包含英文播报实时变声的最终链路 | 暂缓交付 | 当前播报直接送 ALSA，缺少实时变声接入 |

首版建议固定一套硬件、一套音频接线和一套已验证模型。
交付功能包括实时变声、翻译字幕、英文流式播报和已声明的文件转换范围。
英文播报实时变声按用户最新要求计入主链路。

## 已有基础

- 原生 HTTP 已有连接、请求大小、读取及写入截止时间，并支持退出时中断客户端。
- 文件任务使用串行队列，FFmpeg 使用参数调用，取消时回收子进程。
- 模型已有缓存回收、运行时资产及回退原因查询。
- 字幕读取与翻译已通过 `CaptionDispatcher` 解耦，覆盖优先队列已落盘。
- 播报已有早期音频、连续变速、取消、音频预算和独立 FFmpeg 核验。
- 模型导出检查权重缺失及多种动态长度；本轮保留现有数值验收条件。
- CI 已覆盖原生、Python 和前端基础回归。

这些能力继续保留，后续修复围绕现有组件进行。

## P1：首版交付阻塞项

### D01：英文播报缺少实时变声接入

代码确认：[speech_service.py](../../tools/speech_service.py#L651) 使用 `TempoPlayer` 或直接调用 `aplay`。
[tempo_player.py](../../tools/tempo_player.py#L58) 将过滤后的 PCM 直接送入 ALSA 播放进程。
该路径没有实时 RVC 输入、回包、排空和取消管理。
[tts2rvc.py](../../tools/tts2rvc.py) 是独立 Matcha 演示，未接入 PocketTTS 服务。

影响：当前字幕播报与麦克风变声是两条独立路径，最终英文输出缺少用户要求的变声阶段。
直接把两个客户端接到现有同一 UDP 实例，会受到 D05 的客户端归属问题影响。

解除条件：明确两路音频的模型实例、输入归属和输出设备。
接入 PocketTTS 的有序早期 PCM，再接实时 RVC。
以同一英文输入核对时长、包序号、音质、取消、排空和整机资源。
合并前后的队列等待分别统计。

### D02：翻译覆盖、内容重复和错误音频输出存在缺陷

历史实测：最新固定重放处理 175/175 个源段，播报完成 166/175，翻译失败 8 个，合成失败 1 个。
源事件至首 PCM 的等待中位数为 8.752 s，P95 为 14.094 s；计时及配置见[积压修复报告](../backlog-fix-20261019/RESULTS.md)。

同一父段的带前文译文重复“高中同学问”，英文原速为 13.040 s；独立翻译为 10.240 s。
完整父段时长、重复内容和单例上下文对照由[父段复核](../backlog-fix-20261019/PARENT-DURATION-AUDIT.md)维护。
当前 [translate](../../tools/subtitle_bridge.py#L115) 只检查整条候选与历史译文完全相同。
部分重复会通过该检查。

口语数字“两万七”“一千五”与异常源识别仍产生误拒或错误解释。
早期播报还能在合成最终失败前输出部分音频，已有失败记录保存实际输出。

解除条件：扩展上下文对照，按人工确认源文检查事实、数字、否定、人称和重复内容。
固定全部源段分母，分别列出检查通过、合成完成、实际播出和错误播出。
给异常文本建立合成前处理规则，并保留晚到错误及已输出音频的状态。
根据用户可接受的覆盖率和等待制定验收值，再执行最终联合测试。

### D03：启动就绪与运行模式缺少统一状态

代码确认：[启动器](../../tools/run_translated_speech.py#L237) 在线程中等待播报预热，同时继续启动翻译、字幕和采集。
翻译进程启动后没有等待模型就绪。
采集启动位置为 [275 行](../../tools/run_translated_speech.py#L275)。
现有回归明确要求采集先于播报预热完成，见 [test_runner_degraded.py](../../tools/tests/test_runner_degraded.py#L40)。

若初始字幕在参考音色会话启用前到达，播报事件返回 `speech session disabled`。
翻译模型加载期间，请求可以失败。
源字幕继续工作是现有降级设计，但界面缺少“完整就绪／仅字幕可用”的统一区别。
[健康接口](../../api/src/http_api.cpp#L519) 只返回进程存活。

解除条件：保留仅字幕降级能力，同时增加明确的产品运行模式。
完整播报模式在翻译、目标音色、合成运行时和输出设备就绪后允许开始输入。
启动失败或降级原因应进入可查询状态及界面。
停止和再次开始应覆盖采集、识别、翻译、播报及变声的生命周期。

### D04：物理播放失效后，采集进程仍报告成功

本轮实测：使用 ALSA `null` 采集，指定不存在的输出设备并发送 2 帧。
程序记录“无法打开播放设备……仅发送模式”，最后返回退出码 0。
完整命令和结果见 [playback-probe.json](playback-probe.json)。

根因位于 [main.c](../../preprocessor/src/main.c#L92)：播放线程打开设备失败后直接返回。
线程创建失败也退化为仅发送；播放写入失败没有传递到主线程退出状态。
用户可以看到处理仍在运行，同时没有声音。

解除条件：显式请求播放时，将设备打开和持续写入结果反馈给控制面。
区分“用户选择仅发送”和“播放故障”。
覆盖错误设备、设备占用、运行中拔出、重新插入及再次启动。

### D05：UDP 客户端重连后，输出仍绑定旧地址

本轮实测：客户端 A 发送第一帧并收到回包；客户端 B 发送第二帧。
A 收到携带第二帧序号的 3860 B 回包，B 未收到回包。
该探针使用现有 IO 静态库，结果见 [udp-probe.log](udp-probe.log)。

根因位于 [udp_stream.cpp](../../IO/src/udp_stream.cpp#L340)：首个有效发送者被保存为回复目标。
后续有效包会继续入队，但发送者变化既不更新目标，也不拒绝该输入。
重启麦克风客户端通常会分配新 UDP 端口，因此仅重启客户端即可触发无输出。

解除条件：定义单客户端会话的获取、释放、超时及重新绑定规则。
其他发送者的包应得到明确处理，避免混入当前音频。
覆盖客户端退出、换端口、后台仍运行及第二客户端竞争。
ASR 入口同时检查帧序号缺口；当前 [stt_service.py](../../tools/stt_service.py#L212) 解包后没有处理 `idx` 连续性。

### D06：默认局域网访问缺少控制权限边界

代码确认：普通 [RVC 配置](../../rvc-backend/config.yaml#L28) 将音频和控制服务绑定到 `0.0.0.0`。
[HTTP 路由](../../api/src/http_api.cpp#L419) 没有认证或来源检查，即可切模式、改参数、提交任务和代理音色操作。
字幕 SSE 还设置 `Access-Control-Allow-Origin: *`。
仅播报配置使用回环地址，但 [Vite](../../frontend/vite.config.ts#L7) 允许局域网访问并代理这些 API。

影响：能够访问服务端口的其他设备可控制处理、读取字幕和获取可下载结果。

解除条件：确定交付为设备本机使用还是局域网控制。
本机版本默认绑定回环；局域网版本加入配对或访问凭据，并约束浏览器来源和音频发送者。
用未配对客户端验证读写请求均被拒绝。
本项适用于设备外部访问的交付形态。

### D07：部署产物与依赖缺少完整交付包

代码确认：启动器默认使用用户主目录中的模型及归档版 `llama-server`。
仓库没有完整 Python 运行环境锁定文件、安装目标、设备服务单元或统一升级回滚入口。
前端部署说明仍使用开发或预览服务器。
已存在早期 PocketTTS 构建脚本和资产哈希，应纳入统一版本清单。

本轮本机 Python 回归执行 231 个测试，出现 2 个失败和 24 个错误记录，包含子用例。
这些记录均涉及现有 `libmozart-tempo.so` 依赖缺失的 `libavfilter.so.11`。
本机提供 `libavfilter.so.7`。
[tempo_library](../../tools/tempo_player.py#L13) 在发现共享库文件后直接加载，加载失败会阻断变速播报。
原始结果见 [python-unsandboxed.log](python-unsandboxed.log)。

解除条件：发布固定硬件对应的二进制、依赖、模型、配置及 SHA-256 清单。
提供安装、启动、日志导出、升级、回滚和卸载步骤。
在干净设备环境执行安装到出声的验收，检查原生库版本及动态链接依赖。
列出第三方程序、模型和音色资产的来源及分发材料，补齐项目许可文件。

### D08：最终产品配置缺少完整联合验收

历史实测：原组合长测在 4 帧后端丢弃后失败；原证据见[组合长测](../soak-20261019/RESULTS.md)。
完整独立变声、静态播报、固定字幕重放和单父段上下文对照分别回答不同问题。
当前交付证据分布在不同配置中，缺少覆盖最新源代码、英文实时变声和最终物理输出的同一份记录。

解除条件：先完成主链路接入及本报告中的关键故障修复，再冻结发布候选。
使用固定完整文件运行实时识别、翻译、早期播报、最终实时变声和实际输出。
记录全部源字幕分母、完整音频、丢帧、欠载、排队、首音、内存、swap 和退出情况。
增加麦克风操作、冷启动、重复启停、断网、设备拔插及服务退出场景。
人工核对代表性源文、英文内容和听感。

## P2：长期运行与可维护性问题

### D09：任务、字幕和日志缺少统一存储上限

代码确认：覆盖优先模式将任务存入 SQLite，等待队列不设数量或磁盘容量上限。
12 s 限制控制待播音频缓冲，不限制磁盘等待任务。
[StableClauseDispatcher](../../tools/stable_clauses.py#L86) 持续保存父字幕记录，没有历史回收路径。
字幕 JSONL 和工作日志持续追加。

文件任务的终态历史一直保留在 [jobs_](../../rvc-backend/src/state/mode_controller.cpp#L229)，状态接口每次返回全部历史。
文件缓存只在任务结束后清理，待处理文件及上传文件受保护。
文件队列与任务状态也没有跨重启恢复机制。

解除条件：为数据目录设置空间预算、低空间状态、历史保留和日志轮换。
按覆盖优先策略停止接收新工作或暂停采集，保留已接收任务。
明确取消、重启、历史清理和结果过期后的下载行为。
用小磁盘配额复现写满，验证已有任务和状态记录。

### D10：配置错误会被静默替换或转换成极大值

本轮实测：`pitch_shift: high` 被读为默认 0；控制端口 `-1` 转换为 65535；队列深度 `-1` 转换为 18446744073709551615。
结果见 [config-probe.json](config-probe.json)。
根因是 [Config 读取器](../../rvc-backend/src/utils/config.cpp#L72) 对类型错误返回默认值，调用方又转换为无符号类型。
对应位置为 [daemon.cpp](../../state/src/daemon.cpp#L74) 和 [87 行](../../state/src/daemon.cpp#L87)。

解除条件：在配置入口一次性检查类型、范围和必要字段。
字段存在但非法时明确失败，并显示键名和值。
覆盖负数、过大端口、错误布尔值和非有限浮点值。

### D11：识别复核结果仅用于展示，未参与已提交翻译的处置

本轮受控实测：先提交“这是可能的”最终事件，等待翻译和播报请求完成，再提交“这是不可能的”复核事件。
系统已发送 1 个播报请求；字幕继续保持 `translation_status=completed`，新增极性冲突字段。
结果见 [refinement-probe.json](refinement-probe.json)。

根因位于 [CaptionDispatcher.accept](../../tools/subtitle_bridge.py#L267)：异步复核只更新字幕展示字段。
[translate_recognized_event](../../tools/subtitle_bridge.py#L157) 检查的是翻译时已有的事件字段。
晚到的复核结果不会取消、替换或更正已提交播报。

解除条件：明确低延迟在线识别与复核确认两种策略。
对未开始播放的错误任务执行取消或更正。
对已经播放的内容记录更正状态，并在界面明确冲突。
保留在线字幕不被慢复核阻塞的能力。

### D12：界面缺少实际故障与积压状态

代码确认：[SpeechPanel](../../frontend/src/SpeechPanel.vue#L8) 没有展示 `warmup_error`、`storage_warning`、音频积压和运行时就绪状态。

解除条件：让按钮名称与实际控制对象一致。
显示启动中、就绪、仅字幕可用、输出故障和队列延迟。
提供完整处理链路的开始、停止及故障恢复入口。
保留输入电平和输出试听能力，以便用户定位接线及声卡问题。

### D13：字幕断线后缺少补发，部分延迟指标含义不一致

代码确认：[SSE 初次连接](../../api/src/http_api.cpp#L562) 从 JSONL 末尾读取，未使用事件 ID 或断线位置。
[前端](../../frontend/src/App.vue#L361) 自动重连后没有补取当前字幕快照。
断线期间的字幕及修订会从界面遗漏。

[AudioWorker](../../rvc-backend/src/rvc/audio_worker.cpp#L130) 给缓冲后的音频复制当前输入帧元数据。
[延迟统计](../../rvc-backend/src/rvc/audio_worker.cpp#L160) 使用这个当前输入时间计算，实际测量的是包龄。
预处理器日志已经使用 `packet_age` 名称，后端仍将该值放入 `latency`。
UDP 丢弃计数在流关闭时输出，未进入当前状态中的流统计。

解除条件：提供字幕快照或按事件 ID 补发。
统一包龄、推理块耗时、首音等待和物理输出延迟的字段与说明。
将传输丢弃与推理丢块分别暴露给状态及诊断记录。
使用可定位的固定声音标记验证物理端到端延迟。

### D14：文件转换的模型能力与执行预算未完整表达

代码确认：[模型列表](../../rvc-backend/src/state/mode_controller.cpp#L507) 将只有 split Generator 的实时模型列为可选。
前端文件模式使用同一模型列表，没有按文件转换能力过滤。
[离线推理](../../rvc-backend/src/rvc/inferencer.cpp#L180) 要求普通 Generator，选择实时专用模型后会在执行时失败。

文件输入已有 300 s 上限，推理在阶段间检查取消；底层模型调用仍为整次执行。
长输入的特征提取可以使用整段 PCM，并在 TensorRT 形状范围外选择 ONNX。
相关内存及取消预算需要纳入发布候选的资源验收。

解除条件：按模型暴露实时和文件能力，提前阻止不支持的组合。
对最长支持文件执行峰值内存、耗时、取消及退出测试。
若长输入资源超出目标预算，使用有界分块并按 Golden 顺序核对输出。

每个发布候选生成代码、配置、模型、运行时及测试证据清单。

本轮故障注入：让 `numeric_audit` 抛出 `AssertionError`，外层函数返回正常文本和 `numeric_check_failed` 标记。
内部异常没有向上传递，见 [internal-error-probe.json](internal-error-probe.json)。
根因位于 [asr_checks.py](../../tools/asr_checks.py#L89)：同一个宽泛捕获同时包含识别调用与内部数字检查。
该实现对应 AGENTS.md 明确列出的不合格示例。

参数约束也分布在 [RealRVCPipeline::set_parameters](../../rvc-backend/src/rvc/pipeline.cpp#L112) 和 [save_preset](../../rvc-backend/src/state/mode_controller.cpp#L449)。
音高、保护比例等阈值分别定义，后续修改容易导致实时参数与保存预设的范围不同。

解除条件：只捕获能够处理的识别调用错误，让内部检查错误向上失败。
将 RVC 参数约束归入一个定义，由两个外部入口调用。
为实际非法输入保留正反例，避免增加仅测试可触发的内部守卫。
