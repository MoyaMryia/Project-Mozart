# 变速上限 1.50 倍

日期：2026-10-20，新加坡时间。
按用户要求，灵活变速默认上限从 1.15 倍提高到 1.50 倍，为积压留出余量。
控制器仍按源区间和积压逐段选择比例，多数任务的实际比例由需求决定，不使用上限。
原有 1.15 倍证据保留在 [1.15 倍验证报告](../tempo-limit-20261016/RESULTS.md)。

## 识别对照

## 播放一致性

原生过滤器与 FFmpeg 命令行逐采样一致。
采样率对照为 8000、16000、22050、24000、32000、44100 和 48000 Hz，比例 1.5，共 7 组。
分块对照在 24000 Hz 下使用 7 个比例和 3 种输入分块，共 21 组。
比例为 1.037、1.100、1.150、1.200、1.300、1.400 和 1.500。

| 检查 | 结果 |
| --- | --- |
| 板端变速测试 | 6/6 通过，FFmpeg 8.0.1 |
| 板端 Python 回归 | 217/217 通过 |
| 主机 Python 回归 | 217/217 通过，FFmpeg 4.4.2 命令行路径 |
| 板端原生回归 | 25/25，状态生命周期 14 项各重复 10 次 |
| 上限一致性 | 测试读取 C 宏并与 Python `MAX_TEMPO` 比较 |

## 改动

- `tools/tempo_control.py` 的 `MAX_TEMPO` 与 `preprocessor/src/tempo_filter.c` 的 `MOZART_MAX_TEMPO` 同步为 1.5。
- 控制器、命令行、基准脚本和文档使用同一上限。
- 用 `--playback-tempo-max 1.15` 可恢复此前上限。

## 适用范围

- 配置：Jetson Orin Nano 8 GB、FFmpeg 8.0.1、SenseVoice int8 英语模式、PocketTTS int8、2 线程；主机为 x86-64、FFmpeg 4.4.2，仅运行 Python 与命令行路径。
- 样本：识别对照 12 条 × 9 个比例 = 108 个音频，分两批运行；积压分布取自 207 段静态配对；播放一致性 7 种采样率的比例对照与 21 组分块对照。
- 人工试听未执行。阻塞：需要评审人试听 1.15、1.30、1.40 和 1.50 倍的样本。解除条件：试听后记录听感结论，再决定是否保留 1.50 倍。
- 音高对照未重跑。阻塞：板端环境缺少 librosa，RMVPE 工具无法导入。解除条件：恢复依赖后按 2026-10-16 的方法重跑逐句音高差。
- 物理声卡首播延迟未重测。阻塞：需要现场声卡与回录接线。解除条件：确认接线后按 2026-10-16 的方法重测。
