# 覆盖率优先与磁盘队列

日期：2026-10-08。实现提交：`bc73b38`。

默认策略已改为覆盖率优先。等待时间和队列积压不再触发翻译跳过、播报拒绝或首播过期。
Jetson 单轮回放完成了 21／21 个有效译文播报任务；旧配置完成 20／21 个。
以最终识别句为分母，覆盖率从 20／23 增至 21／23。两条翻译检查失败仍保留。
本次没有改变模型、生成步数、语速和片段顺序。

## 实现范围

- 启动器、字幕桥和独立播报服务默认使用 `--delivery-policy coverage`。
- 翻译与播报的等待任务写入 SQLite 磁盘队列。内存只保留有限的任务记录缓存。
- 服务按先入先出顺序处理任务。积压可以增加等待时间，不再受原来的 30 s 首播时限约束。
- 文件输入结束后，启动器等待翻译和播报队列处理完毕，不再套用固定清理时限。
- 正常退出保留等待任务。重启恢复尚未开始播放的任务。
- 已经开始但被中断的播放不会自动重播。明确停止操作仍取消播报任务。
- 生成音频仍受原来的 12 s 缓冲限制。WAV 保存在磁盘，不把全部积压转换为内存中的音频。
- `--delivery-policy realtime` 保留原来的延迟预算，供需要时回退。

输入校验、翻译检查、引擎错误和明确取消仍可能阻止播报。
启动阶段的模型不可用、服务故障和磁盘写入失败也没有变成自动重试保证。
状态接口新增全队列的 `unfinished_jobs` 与 `pending_jobs`，避免只根据最近任务判断处理完成。
接口细节见 [播报说明](../../tools/REFERENCE_SPEECH.md#admission-and-deadlines)。

## Jetson 实测

设备为 Orin Nano Super。图形服务保持运行。
PocketTTS 使用 CPU int8、2 线程；翻译使用 Qwen 0.8B Q4_K_M。
输入为同一份保留的 120 s 预处理 WAV；不重复执行 RNNoise，RVC 关闭。
输出使用按音频时长等待的 ALSA `null`。本轮没有实体扬声器测试或人工听检。
模型、参考 WAV、原生二进制及工具文件摘要见 [数据汇总](coverage-results.json)。

历史控制组为 `limit128-v1`。新测试为 `coverage-v1`，只运行一遍。
设备端工具摘要与本地实现提交一致。全部 23 条最终源文本和 21 条成功译文与控制组相同。

本次结果说明覆盖率增加，不能证明长时间连续输入的等待有界。

49 个播放片段顺序正确。28 个句内交界超过 20 ms 的数量为零。
原生采集完成 6,000 帧，输入溢出为零。字幕修订顺序正确。

测试程序以状态码 0 退出，总耗时为 151.21 s，包含启动、120 s 输入与积压处理。
结束时，未完成播报数、等待播报数和翻译队列行数均为零。

## 内存与 swap

本轮最低可用内存为 4.297 GiB。未触发 768 MiB 内存保护。
测试开始和结束时已有的 swap 占用均为 172,269,568 bytes，约 164.3 MiB。
本轮 swap 换入、换出页数均为零。该已有占用不能归因于本次补丁。
应用没有修改系统 swap 设置，也没有强制把模型换出。
待处理文本直接落盘，可以避免让长期积压全部驻留内存。
swap 可以缓解内存压力，但不能缩短合成计算或实际播放时长。

## 验证与边界

本地 115 项 Python 测试通过，前端生产构建通过。
新增测试包括 200 个播报任务排队、150 个翻译任务排队、缓存淘汰后继续处理、顺序保持、
重启恢复、队列独占、明确停止，以及中断播放后不自动重播。
JSON 快照和 WAV 临时文件现使用不同名称，避免并发保存时互相覆盖。

有限时长回放不代表长期压力测试。队列仍受磁盘空间限制。
如果输出持续比输入长，延迟仍会增加。该策略优先保留内容，没有提高实际播放速度。
原始日志、数据库和 WAV 保存在 `rvc-golden/realtime-patches-20261008/coverage-v1`，由 Git 忽略。
