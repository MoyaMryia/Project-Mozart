# 翻译检查失败后的文字与语音输出

日期：2026-10-09。实现提交：`b5a359c`、`df93ef9`。

翻译检查失败后，系统保留最后一个非空候选译文，并继续请求播报。
检查失败状态不会改成成功。界面标注“待核对译文”，并保留失败原因。
候选译文没有通过检查，可能包含错译、数字错误、中文残留或截断。
该行为按本次用户要求优先保留输出，不代表译文质量通过验收。

## 本次修复

- 数字检查不再把“七千五千”相加为 12,000。该歧义文本保持原样，不推断两个数之间的关系。
- `en` 保存最后一个非空候选译文。没有候选时，原文和错误仍可见。
- 新的部分字幕到达后，界面仍保留前文候选译文，并标明未通过检查。
- 开启播报时，系统发送 `speech_degraded: true`，让候选文本继续进入语音引擎。
- 播报服务保存降级标记。该标记允许英文候选中的中文字符通过文本检查。
- 界面分别显示翻译错误和播报错误，避免翻译警告遮住播报失败。

英文引擎没有经过验证的中文发音能力。本次没有替换候选中的中文，也没有声称能正确读出这些字符。
如果翻译服务未返回任何候选，系统保留原文与明确错误，不凭空生成译文。
语音引擎故障、音频幅值检查和生成长度限制仍可能阻止播报。
接口行为见 [播报说明](../../tools/REFERENCE_SPEECH.md#translation-and-asr-limits)。

## 本地验证

120 项 Python 测试、8 项前端测试和前端生产构建通过。
新增用例覆盖数字误判、中文残留、数字检查失败、输出截断、重试超时、没有候选，
以及播报服务拒绝未标记混合文本、接受明确标记的降级候选。
测试确认检查失败仍保留失败状态，并向语音服务发送候选文本与降级标记。

首轮 Jetson 测试 `fallback-v1` 暴露了播报服务的第二层语言检查，返回 HTTP 422。
该轮已主动停止，不用于完整回放的覆盖率统计。
后续实现使用明确的降级标记处理此情况，普通请求仍保留原来的语言检查。
