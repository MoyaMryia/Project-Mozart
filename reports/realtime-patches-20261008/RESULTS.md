# 实时字幕补丁的 Jetson 短测

日期：2026-10-08。测试提交：`8bf2a46`，包含三个临时补丁。
本轮支持保留补丁。慢翻译和可选复核没有阻塞后续中文字幕。
播报仍有明显积压，不能据此声称已经实现低延迟语音翻译。

## 配置与范围

- 设备使用 SSH 别名 `jetson`。代码位于独立目录 `/home/moyamryia/mozart-realtime-patches-20261008`。
- 原仓库 `/home/moyamryia/Mozart` 保持在 `fd9a0fc`，其已有修改保持不变。
- Python 工具来自测试提交。原生服务复用设备已有 `build-gpu` 二进制，未重新编译。
- 在线识别使用 Zipformer 14M。翻译使用 Qwen 0.8B Q4_K_M 和 CUDA。
- 播报使用 Pocket TTS int8、CPU 两线程、五步生成及固定种子 42。参考音色为既有 Qiqi WAV。
- 两轮正常测试使用同一份已预处理的 120 s 输入。第三轮只回放前 60 s。
- 输入为 `rvc-golden/sentence-context-20261007/processed-source-120s.wav`。没有再次运行 RNNoise。
- 播放使用按音频时长计时的 ALSA `null` 设备。RVC 保持关闭。

原视频已不在设备临时目录中。本轮复用了保留的处理后输入，不能与旧报告中的原视频测试直接比较。
每轮记录了输入、参考音频、翻译模型、Python 工具及原生二进制的 SHA-256。
三轮 Python 工具的摘要均与 `8bf2a46` 一致。
本轮没有关闭 GNOME 或其他系统服务。

## 故障降级

`failure-v1` 回放 60 s。在监督程序启动约 30 s 后，测试脚本停止本轮拥有的翻译和播报服务。
测试没有停止原仓库进程或系统服务。

故障后，中文字幕继续产生 70 次临时更新和 7 个最终结果。
整轮完成 3,000 帧采集，输入溢出为零。
翻译共完成 4 句、失败 9 句。后者包含两条文本检查拒绝和七条故障后的连接失败。
播报共完成 2 / 4 个已接收任务，其余两个由本次故障关闭过程取消。
这些取消属于故障注入结果，不能计为正常回放失败率。

三轮监督程序均以状态码 0 退出。脚本检查没有发现本轮残留进程。
测试后，相关服务端口均已释放。设备可用内存约为 5.5 GiB，交换空间使用量为零。

## 剩余问题

1. **播报延迟仍大。** 两轮的首片合成中位数约为 1.7 s，播报提交至首播却约为 12.1 s。
   后者包含等待、预算控制、合成及播放排队，不能全部归因于模型计算。
   下一步应分别记录各段等待时间，再调整播放积压和过期任务策略。
2. **字幕传输存在固定轮询等待。** 当前 `api/src/http_api.cpp` 的 SSE 循环每次等待 200 ms。
   实测约 100 ms 的接收中位数与该周期一致。这是待验证的优化点，本轮没有修改原生服务。
3. **翻译和播报仍会漏句。** 本输入中两句被文本检查拒绝，一句播报被容量限制拒绝。
   需要在界面明确显示原因，并单独统计覆盖率。
4. **翻译存在长尾。** 两轮翻译计算最大值均约为 6.9 s；后台线程只能避免阻塞字幕。
   下一步可核对长尾请求的输入长度、输出长度和生成截止条件。

资源记录覆盖启动、回放和收尾。每轮约 149 个 GPU 样本，采样周期为 1 s。
两轮 GPU 平均利用率分别为 11.84% 和 11.51%，最大值均为 99%。最高 GPU 温度为 57.53 °C。
交换空间使用量和换入页数均为零。
本轮没有证据表明 GPU 持续饱和，但 1 s 采样可能漏掉短峰值。
这不是 GPU 满载压力测试，也没有验证 GPU 语音合成的收益。
