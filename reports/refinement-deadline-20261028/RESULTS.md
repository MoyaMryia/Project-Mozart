# 复核截止时间的本地回归

本次修复消除了出队后重新启动完整复核窗口的问题。
复核窗口从桥接进程接收最终识别文本时开始，原文处理和排队均消耗该窗口。
选择规则与质量检查保持不变。

## 确定性调度测试

以下数值来自可控单调时钟测试。模拟翻译函数阻塞第一条任务，使第二条任务进入队列。
测试把复核窗口固定为 `1 s`，记录第二条任务在复核函数内的等待时间。
基线为 `d869b23`。

| 第二条任务状态 | 基线等待 | 修改后等待 |
| --- | ---: | ---: |
| 排队 400 ms，候选未返回 | 1000 ms | 600 ms |
| 排队 2000 ms，候选未返回 | 1000 ms | 0 ms |
| 原文处理 250 ms，排队 500 ms，候选未返回 | 1000 ms | 250 ms |
| 排队 2000 ms，候选已返回 | 0 ms | 0 ms |

修改前，前三个断言失败。修改后，四个调度测试全部通过。
就绪候选继续接受术语、数量、极性和识别审核检查。

## 恢复队列

复核截止时间与队列所属实例一起保存。
新实例恢复旧任务时，跳过已经失效的等待过程，并记录选择原因。
兼容性测试覆盖队列项目的内联复核字段契约。当前识别进程通过单独事件发布复核结果。
旧任务不会读取新会话中相同序号的复核候选。

恢复测试覆盖带旧实例标识和不带实例标识的两种旧格式。
旧任务不消费当前会话候选，当前会话随后仍能采用该候选。
识别审核有冲突时，即使候选已就绪且窗口已过，翻译与播报请求仍被阻止。
