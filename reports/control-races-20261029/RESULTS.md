# 设备草稿与停止控制修复

本轮修复设备选择被轮询覆盖、总停止错误被忽略，以及停止后旧控制请求重新执行的问题。
模型、识别、翻译与音频质量验收规则保持原样。

## 修改

- 设备表单保留待应用的草稿，其余字段跟随后端当前设置。
- 状态断开后重连时，表单保留草稿与最近的状态基线。
- 总停止显示播报请求失败及部分停止失败。程序错误继续向上抛出。
- 每次显式停止递增并持久化控制代次。
- 前端在创建会话、准备和试听请求时附带当前代次。
- 后端在执行控制请求前拒绝旧代次，返回 409。

控制代次独立于系统时间。测试在固定系统时间下连续停止，两次代次仍然不同。
请求字段、返回值和兼容行为见[播报接口](../../tools/REFERENCE_SPEECH.md#api)。

## 本地验证

前端测试覆盖草稿轮询、后端设置更新、应用后的基线更新、断开重连，以及取消后迟到的试听请求。
后端测试在实时与覆盖两种策略下投递旧会话、准备和试听请求。
旧请求被拒绝后，新代次可以恢复准备、启用和合成。
另外检查停止代次重启持久化、非法配置和旧状态文件迁移。
移除代次守卫后，原用例因旧控制请求获准执行而失败，见[反例记录](generation-guard-mutation.json)。

浏览器记录见[browser-evidence.json](browser-evidence.json)。
浏览器检查设备草稿跨越轮询保持不变，并检查总停止的 HTTP 失败与部分失败提示。

## 适用范围

- 配置：本地主分支 `5f561da` 基础上的修改；模拟工作进程、模拟接口；Chromium `151.0.7922.34`。
- 样本：64 项前端自动测试通过；620 项 Python 测试中，615 项通过、5 项跳过。后端控制用例覆盖两种投递策略和三类旧控制请求；浏览器使用两个视口。
- 代次验收使用实现新协议的前后端。请求字段的兼容规则由播报接口文档维护。
- Jetson 部署与真实播放的验收条件见[播报调查](../speech-latency-20261029/RESULTS.md#适用范围)。
