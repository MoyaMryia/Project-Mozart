# 原生 USB 全双工对传实测

日期：2026-10-25。生产源码版本：`5b20c6029b9a091e43292284c544e8023397669f`。
本轮接续[专用端点与预处理基线](../usb-latency-baseline-20261025/RESULTS.md)。

## 结论

现有 FunctionFS bulk 通道完成原生全双工对传。
三轮正式测试共传输 **135000/135000 个音频负载包**，两个方向的序号和逐字节内容全部匹配。
64 样本块的 60 s 对传期间，控制探针往返中位数为 **0.112 ms**，P99 为 **0.228 ms**，最大值为 **0.324 ms**。
这些数据支持继续使用现有 bulk 端点，下一阶段处理本机音频队列和调度。

## 设备与路径

实际设备为 `Bus 003 Device 020: ID 1d6b:0105 Linux Foundation FunctionFS Gadget`。
主机通过设备描述符发现 interface 1 的 bulk OUT `0x02` 和 bulk IN `0x82`。
USB 速率为 480 Mbps。

```text
本机独立发送线程 ── bulk OUT ──▶ Jetson 接收线程
本机接收线程     ◀─ bulk IN  ── Jetson 独立发送线程
```

两端按各自单调时钟定时发送，不等待对方音频回包。
负载按 48 kHz、双声道、S16 的速率生成。
每个方向的音频负载速率为 **192000 B/s，即 1.536 Mbit/s**。
64 样本块每方向每秒 750 包；128 样本块每方向每秒 375 包。
包头为 24 B，音频负载分别为 256 B 和 512 B。

主机使用原生 C++/libusb，Jetson 使用原生 C++/FunctionFS。
测试进程使用默认 `SCHED_OTHER`，未改变 CPU governor。
Jetson 的接口 0 守护进程保持运行。本机原有 USB 桥在测试期间停止，结束后恢复。
未修改驱动、内核、UDC 绑定或生产代码。

## 数据与时间校验

两个方向使用不同的确定性种子生成负载。
接收端逐包检查版本、流、长度、连续序号和全部负载字节。
任一错误导致测试失败。两端另外核对最终收发计数。
分片与合并帧由流式解析器处理。

主机每发送 128 个音频包，额外发送一个 24 B 控制探针。
Jetson 接收线程把该探针原样回写，与独立下行音频共享 IN 端点。
往返计时从主机提交探针前开始，到主机读取完成后结束，全程使用主机同一单调时钟。
控制探针的 RTT 表示并行音频负载下的应用层控制往返时间。

读取完成时刻也是完整协议包可由应用取得的时刻。
同一批读取中的多个包共用时间戳，分片包使用最后一片读取完成的时刻。
两端单调时钟没有直接相减。

## 正式测试结果

| 块长 | 时长 | 每方向发送／接收 | 探针数 | RTT 中位数 | RTT P99 | RTT 最大值 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 64 | 60 s | 45000/45000 | 352 | 0.112 ms | 0.228 ms | 0.324 ms |
| 128 | 20 s | 7500/7500 | 59 | 0.141 ms | 0.250 ms | 0.250 ms |
| 64 | 20 s | 15000/15000 | 118 | 0.117 ms | 0.214 ms | 0.258 ms |

三轮共收到 **529/529 个控制探针回包**。
RTT 分位数使用 nearest-rank。全部探针均纳入统计，最大值保留。
音频发送线程相对计划时刻的最大迟到量为：本机 **0.546 ms**，Jetson **0.165 ms**。

正式测试前另做一次 64 样本块、3 s 预检。
预检两个方向各收到 **2250/2250 包**，18/18 个控制探针返回。
预检数据独立保存，未计入正式测试表。

审查后将块长范围集中到共享头文件，并补齐命令行整数的完整解析检查。
64 与 128 样本块各复测 3 s，两个方向分别收到 **2250/2250 包**和 **1125/1125 包**。
两轮共收到 27/27 个控制探针回包，数据另存于 `post-review-b64-3s/` 和 `post-review-b128-3s/`。
负载破坏、错序、拆包、合包、错误 magic 和超长负载检查均通过；无效整数参数明确失败。

首次后台启动在正式采集前中止，清理流程终止了该进程。
随后使用有运行超时的临时 systemd 服务执行正式测试，各轮正常结束。
`rvc-golden/usb-latency-20261025/duplex/remote/mozart-usb-duplex-20261025/b64-60s-r1.log` 保留首次中止记录和随后正式轮次的成功记录。

## ALSA 前置试验记录

纯 USB 对传之前，原生 ALSA 测试泵接入了独立 Loopback 子流 2 和 3。
该试验保留启动前 100 包预热，随后逐包播放。
所有欠载均返回错误并停止，未用重启或丢帧维持成功状态。

| 配置 | 已播放／目标包数 | 结果 |
| --- | ---: | --- |
| echo，64，缓冲 4 周期，预填 2 周期 | 266/2250 | 播放欠载，失败 |
| echo，64，缓冲 6 周期，预填 3 周期 | 447/7500 | 播放欠载，失败 |
| DSP，64，缓冲 6 周期，预填 3 周期 | 5781/7500 | 播放欠载，失败 |
| DSP，128，缓冲 4 周期，预填 2 周期 | 48/3750 | 播放欠载，失败 |
| echo，64，两端 FIFO 20，缓冲 6 周期，预填 3 周期 | 7500/7500 | 测试收尾失败 |
| DSP，64，两端 FIFO 20，缓冲 6 周期，预填 3 周期 | 1280/7500 | 播放欠载，失败 |

收尾失败来自探针反复调用非阻塞 `snd_pcm_drain()`。
探针现改为单次启动 drain，再等待状态完成。
修复后按上述 FIFO 20 echo 配置复测 3 s，**2350/2350 包**完整回传，其中 **2250/2250 包**进入播放。
源自采集的 **144000/144000 个立体声采样帧**，经过 USB、播放和 Loopback 回录后逐位一致。
该检查按波形内容对齐，回录前导静音为 192 个采样帧。
播放欠载的失败记录仍保留，后续从本机队列与调度继续定位。

## 工件与复现

本机工件目录为 `rvc-golden/usb-latency-20261025/duplex/`：

- `duplex_common.hpp`：协议、负载生成、校验与分片解析。
- `host.cpp`、`jetson.cpp`：两端原生测试泵。
- `selftest.cpp`：负载破坏、错序、分片、合并、错误 magic 和超长字段的检查。
- `b64-60s-r1/`、`b128-20s-r1/`、`b64-20s-r2/`：主机逐包记录、逐探针 RTT 和计数。
- `remote/mozart-usb-duplex-20261025/`：板端逐包记录、发送迟到量和计数。
- `pilot/`：3 s 预检数据。

ALSA 能力记录在 `rvc-golden/usb-latency-20261025/alsa-capabilities/`。
ALSA 测试源码、失败记录和收尾修复复测在 `rvc-golden/usb-latency-20261025/native-host/`。
测试工件由现有 `.gitignore` 排除，均保留在本机。

主机编译命令：

```sh
D=rvc-golden/usb-latency-20261025
c++ -std=c++17 -O2 -Wall -Wextra -Werror \
  -I "$D/native-host/deps/extracted/usr/include" \
  "$D/duplex/host.cpp" -Wl,-l:libusb-1.0.so.0 -pthread \
  -o "$D/duplex/host"
```

libusb 头文件来自 `libusb-1.0-0-dev` 的解包目录，未安装系统开发包。

板端编译命令：

```sh
c++ -std=c++17 -O2 -Wall -Wextra -Werror \
  /tmp/mozart-usb-duplex-20261025/jetson.cpp -pthread \
  -o /tmp/mozart-usb-duplex-20261025/jetson
```

先停止本机 USB 桥。为退出流程设置服务恢复处理。
在板端启动有超时的临时服务：

```sh
sudo systemd-run --unit=mozart-usb-duplex-test --collect \
  --property=Type=exec --property=RuntimeMaxSec=75s \
  /tmp/mozart-usb-duplex-20261025/jetson /tmp/usb-duplex-run
```

在主机执行：

```sh
sudo rvc-golden/usb-latency-20261025/duplex/host 64 60 /tmp/usb-duplex-host
```

测试后停止剩余测试服务。恢复本机 USB 桥。
本轮已确认两端 `mozart-usb-audio` 均为 `active`，专用端点已释放。
