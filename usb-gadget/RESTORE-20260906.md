## 结论

板载 Tegra234/Orin `3550000.usb` device controller 不支持 ISO device
endpoint。标准 UAC1/UAC2 声卡依赖 ISO，因此本机 USB-C device 模式不能稳定
实现 Windows 免驱麦克风/扬声器。实验中虽能枚举设备，但 EP7 音频流重复产生
`ISO ring error 0xe`，且曾触发内核内存释放错误和 panic。继续修改 TRB、请求
数量或 UAC1/UAC2 描述符不能绕过这个硬件限制。

后来人只有两条路：

1. **写专用驱动/协议。** 使用 bulk endpoint 和 Windows 专用用户态程序，或
   Windows 虚拟声卡驱动加桥接服务；这不再是免驱标准 USB 声卡。现有 Mozart
   UDP 音频契约可以作为处理链内部接口。
2. **购买支持 USB device 音频的 USB 对录线/音频桥。** 关键不是外形，而是
   线内必须有两个 USB 端控制器，并在 Jetson 一侧枚举成可用音频设备或网络/
   bulk 设备。普通 A-to-A 线不是对录线，不能使用。

## 对“两个耳机”对录线的判断

如果这根线在两端分别表现为 USB 音频设备，理论上可以避开 Jetson 的
`3550000.usb` device controller：Windows 端使用线提供的音频端，Jetson
端作为 USB host 使用另一端。它是否真的能双向传输、是否暴露 playback 和
capture、是否需要厂商驱动，必须用具体型号或两端各自的 `lsusb -t`/Windows
设备信息确认，不能仅凭“两个耳机”描述保证。

确认标准：

- Jetson 端应在 `lsusb -t` 中看到 USB audio 或明确的网络/bulk bridge 驱动；
- `aplay -l` 和 `arecord -l` 应分别有播放、录音节点；
- Windows 端应能看到对应的播放、录音设备或桥接网络接口；
- 不应再使用 Jetson Type-C 的 device/gadget 模式；
- 若两端都只是“耳机输出”而没有录音输入，不能满足双向 Mozart 音频链。

恢复后推荐先在无 Mozart gadget 的官方系统上单独验证这根线，再接入现有
`mozart-pre`/UDP/RVC 链路。不要重新启用本目录中的 UAC2 gadget 实验服务。
